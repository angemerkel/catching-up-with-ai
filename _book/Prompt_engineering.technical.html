2  Prompt Engineering

– Technical Summary (with Examples)

A compact, engineering-oriented overview based on your notes.

3 1. LLM Mechanics (Technical Basics)

  • LLMs are autoregressive token predictors: output token tₙ becomes input for tₙ₊₁.

  • Operate on tokenized text → numerical embeddings → transformer layers.

  • Self-attention computes weighted relationships across all tokens.

  • Positional encodings inject sequence order into the model.

  • Training minimizes cross-entropy loss on massive text corpora.

  • Example:

Input: “Variant calling begins with…”
Model predicts tokens with highest probability from training distribution.

4 2. Goal of Prompt Engineering

  • Increase predictability, consistency, and task alignment.

  • Encode task intent + constraints + format clearly.

  • Reduce ambiguity and avoid hallucinations.

Example:
Instead of:

“Explain PCA.”

Technical variant:

“Provide a mathematically grounded explanation of PCA for an R programmer. Include eigenvectors, variance decomposition, and a 3-line code example.”

5 3. Prompt Pattern (Technical Version)

5.1 3.1 Persona Pattern (Functional Control)

Define computational role + constraints.

Example:

“Act as a senior data engineer. Output only SQL, no explanations.”

5.2 3.2 Audience Persona Pattern (Adjust Explanation Level)

Tells the model who the target reader is.

Example:

“Explain transformer attention to someone familiar with matrix multiplication but new to NLP.”

5.3 3.3 Flipped Interaction Pattern (Information Acquisition)

Useful when task requires parameters or architecture definition.

Example:

“Ask me all required questions to define a Snakemake workflow. Then generate the final workflow.”

5.4 3.4 Question Refinement Pattern (Error Reduction)

GPT rewrites your question to reduce ambiguity.

Example:

“Before answering, propose a more precise version of my question optimized for computational reproducibility.”

5.5 3.5 Cognitive Verifier Pattern (Structured Reasoning)

Model decomposes problem → produces final synthesized answer.

Useful to check the model’s reasoning. Improves the output.

Example:

“Break the question into technical sub-questions (≤5), answer them, then produce the final integrated explanation.”

5.6 3.6 Few-Shot Pattern (Pattern Imitation)

Provide input/output examples → model induces rule.

Example:

Input: “ATGGCT”

Output: reverse_complement: “AGCCAT”


Input: “CGTAAT”

Output:

GPT generalizes rule across new inputs.

5.7 3.7 Chain-of-Thought (CoT) Pattern (Explain Reasoning)

Model outputs intermediate reasoning (optional).

Example:

“Show your reasoning in short bullet points and end with a boxed final answer.”

5.8 3.8 ReAct Pattern (Reason + Tool Use)

LLM reasons → takes actions (search, code execution) → final answer.

Example:

“Search the latest ENCODE metadata for a DNase-seq dataset, summarize QC metrics, then evaluate quality.”

5.9 3.9 Evaluation Pattern (Auto-Grading Models)

Provide criteria or examples → GPT scores candidates.

Example:

“Evaluate the following three pipeline descriptions for clarity (1–5), modularity (1–5), reproducibility (1–5). Justify each score.”

5.10 3.10 Template Pattern (Deterministic Structure)

Force GPT to output in a machine-readable or human-readable schema.

Example:

{

“task”: “<TASK>”,

“inputs”: \["\<INPUT_1\>", "\<INPUT_2\>"\],

“steps”: \["\<STEP_1\>", "\<STEP_2\>"\],

“expected_output”: “<OUTPUT>”

}

5.11 3.11 Meta-Language Pattern (Define Custom Syntax)

You define a symbolic shorthand → model learns mapping.

Example:

“Interpret ‘QC-S1’ as: run FastQC → summarize per-base content → output 3 metrics.”

5.12 3.12 Recipe Pattern (Pipeline Definition)

Fill missing steps in a workflow.

Example:

“Insert the two missing steps in this pipeline:

  1. Load FASTQ

  2. Align with BWA

  3. Generate BAM summary”

5.13 3.13 Alternative Approaches Pattern (Algorithmic Exploration)

Generate multiple candidate solutions.

Example:

“Provide 4 alternative strategies for building a FAIR-compliant metadata capture workflow. Rank by implementation cost.”

6 4. Text & Data Manipulation Patterns

6.1 4.1 Semantic Filter

Remove or transform only the targeted elements.

Example:

“Remove all patient identifiers but keep clinical meaning intact.”

6.2 4.2 Tail Pattern (Post-Processing)

Append additional required content automatically.

Example:

“After summarizing the paper, append a list of unresolved questions.”

6.3 4.3 Fact-Checking Pattern

Extract facts → verify → append fact list.

Example:

“Extract all factual claims from the text and mark those that require verification due to missing sources.”

7 5. Structured Input / Output Practices

7.1 5.1 Input Pattern

Prompt instructs model to ask for required missing inputs.

Example:

“Before writing the workflow, ask me for organism, assay type, and sequencing depth.”

7.2 5.2 Outline Expansion (Scalable Generation)

Feed outline → expand specific nodes only.

Example:

“Expand section 3.2 (Data QC) into a 5-step protocol. Leave other sections untouched.”

7.3 5.3 Deterministic Output (Tables, Lists, Checklists)

Essential for automation or downstream parsing.

Example (Checklist):

  • Input validation

  • QC metrics collected

  • BAM index generated

  • Metadata validated

7.4 5.4 Escape Values (Prevent Hallucinations)

Allow model to say “I don’t know.”

Example:

“If information is missing, return <N/A> instead of guessing.”

8 6. LLM + Data Techniques

8.1 6.1 In-Context Learning with Tabular Data

Provide columns + examples → model deduces hidden rules.

Example:

“Given columns A and B, predict column C (protein class) based on observed patterns.”

8.2 6.2 Synthetic Data Generation

Bootstrap ML experiments or testing.

Example:

“Generate a synthetic metadata table of 50 samples with fields: donor_age, diagnosis, cell_type, library_size.”

9 7. ML with Prompts (Your Course Notes)

Classification via Prompting

  • Good for simple yes/no or category labeling.

Example:

“Label each comment as ‘informative’, ‘spam’, or ‘uncertain’.”

Clustering via Prompting

  • Model groups items into meaningful clusters.

Example:

“Cluster the following 30 job descriptions into 5 roles and output an ASCII taxonomy tree.”

Prediction via Prompting

  • Model extrapolates patterns.

Example:

“Given the engagement metrics for existing workshop titles, propose 3 new course titles likely to perform well.”

10 8. Testing & Benchmarking GPT

Test dimensions:

  • Factual accuracy

  • Logical consistency

  • Robustness to ambiguity

  • Formatting fidelity

  • Safety/compliance

  • Cultural/linguistic appropriateness

Example test:

“Provide 3 mutually exclusive interpretations of the following ambiguous policy text. Identify which is most likely intended and why.”

11 9. Reliability, Safety & Boundaries

Preventing Hallucinations

  • Provide context first

  • Add escape values

  • Use verification loops

Boundaries

  • Define scope and constraints clearly.

Example:

“Do not provide clinical recommendations. Only summarize available evidence.”

Ambiguity Management

  1. Identify ambiguous parts

  2. Ask clarifying questions

  3. Fall back to <N/A>

**Conflict Resolution

Use rules:

  • Prefer newest document

  • If only one document covers the topic → use that

  • Otherwise present conditional interpretations.

12 10. Adversarial Input & Guardrails

  • Add validation steps.

  • Disable functionality when constraints are violated.

Example:

“If the input appears to request personally identifiable information, do not answer. Instead return a compliance notice.”
