2.4 Verification and critical use

Published

26 November 2025

These notes are based on the Coursera course Trustworthy Generative AI by Jules White at Vanderbilt University. The previous sections focused on how to interact with AI, work with different types of information and organise more complex tasks as workflows. This section adds another important part of working with generative AI: verifying its outputs and using them critically.

Language models generate text, not necessarily answers. Some of that text may provide useful answers, but even a clear and convincing response can be wrong. This makes verification an important part of working with generative AI.

Why verification matters

Language models generate responses based on patterns learned from data. They can produce incorrect information, make unsupported claims or invent details that appear plausible. These errors are often referred to as hallucinations.

The difficulty is that incorrect answers do not necessarily look incorrect. A response can be fluent and internally coherent while still containing factual errors.

The level of verification should depend on the task and its consequences. A suggestion used for brainstorming does not require the same level of checking as information used in a scientific analysis or an important decision.

When is AI the right tool?

An important part of using AI critically is deciding whether it is appropriate for a particular task in the first place.

Language models can be useful for exploring ideas, working with unstructured information, drafting text, generating code or helping to plan an analysis. However, not every task benefits from involving AI.

For calculations, statistical analyses or data transformations that require precise and reproducible results, conventional computational tools may be more appropriate. AI can still help formulate the approach or generate code, but the actual operations should be performed using methods that can be inspected and tested.

Other considerations include the availability of reliable information, the sensitivity of the data, the consequences of an error and whether the output can be verified.

Before uploading data or documents to an AI service, it is important to consider whether they contain personal, confidential or unpublished information. The service’s data-handling policies and any applicable institutional requirements should be checked before sharing such material.

The question is therefore not simply what AI can do, but whether using AI provides an advantage over existing approaches, given the effort and risks involved.

Checking information and sources

When an answer depends on factual information, an important form of verification is to return to the original source.

Keeping extracted information connected to its source, including document names, page numbers or sections, makes individual statements easier to check.

For example:

Summarise the main findings of these papers. For each finding, identify the supporting paper and section, and provide a short quotation from the original text so that I can verify the interpretation.

References generated by a language model also need to be treated carefully. A citation that looks plausible is not necessarily real, and a real paper does not necessarily support the claim for which it is cited. Both the existence of the source and the connection between the source and the claim need to be checked, including whether any quoted passage accurately reflects the original text.

Checking calculations and analyses

Calculations and data analyses can often be checked independently using conventional computational methods, such as reproducing calculations, inspecting generated code or comparing results with an independent analysis.

Another approach is to test a procedure on a simple case where the expected result is already known.

For example:

Apply this transformation to these five example values and show the result for each value.

The output can then be compared with the expected values before applying the procedure to a larger dataset.

This is particularly important for generated code: code that runs without errors is not necessarily correct. Its behaviour and results still need to be checked against what it was intended to do.

Checking intermediate results

In a multi-step workflow, verification should not be limited to the final result. Important intermediate outputs can be checked before they become inputs to later stages.

Consider a simple workflow:

extract information → organise it → analyse it → produce a summary

If information is extracted incorrectly in the first step, the later analysis may still appear coherent while being based on incorrect input.

Checking intermediate results helps detect errors before they propagate through the workflow and makes it easier to identify where something went wrong.

The cost of verification

AI can produce an answer, analysis or draft very quickly, but generating the output is only part of the work. The result may also need to be checked.

This raises an important question:

How much effort is required to verify the result?

For some tasks, verification is relatively straightforward: a calculation can be reproduced, code can be tested or a statement checked against an identified source. For others, such as evaluating a complex analysis or comparing information across many documents, verification may require substantial work.

The usefulness of AI therefore depends not only on how quickly it produces an output, but also on the cost of establishing whether that output is reliable. Designing workflows with inspectable intermediate results and traceable sources can help reduce that cost.

Domain expertise and human judgement

Some errors can be detected mechanically: a calculation produces the wrong value, a reference does not exist or code fails a test. Other problems are harder to identify. An analysis may use an inappropriate method, an interpretation may overlook an alternative explanation, or a conclusion may go beyond what the evidence supports.

Recognising these problems requires domain expertise and judgement. Someone familiar with the subject may identify implausible assumptions, missing information or methodological problems that are not obvious from the generated answer.

Human expertise therefore remains important throughout the workflow: defining what needs to be checked, evaluating intermediate results and judging whether the evidence supports the conclusions.

Using AI does not transfer responsibility for the resulting work to the model. Anyone incorporating AI-generated information, analyses or text into their work remains responsible for understanding and evaluating what they ultimately use or communicate.
